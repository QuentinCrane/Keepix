# 整理目标与连续 Deck 语义

C05 固定用户设置、会话目标和内存队列使用不同概念。`photoBatchSize` 与 `videoBatchSize` 是本次整理目标，不是内存批大小，也不是一次数据库查询的固定上限。

| 概念 | 照片 | 视频 |
| --- | --- | --- |
| 本次整理目标 | 达到目标后显示本次整理总结 | 达到目标后继续连续整理，目标进度保持 100% |
| Deck 加载窗口 | 内部固定加载窗口，当前为 420 | 内部固定加载窗口，当前为 240 |
| Deck 补充阈值 | 队列不超过 120 项时补充 | 队列不超过 80 项时补充 |
| 用户可见进度 | 已完成动作 / 本次有效目标 | 已完成动作 / 本次有效目标 |

## 进度边界

- 进度完成数只使用本次会话动作数，不把预加载窗口误算为用户已处理数量
- 目标会限制在 1–100；百分比始终限制在 0–100
- 当筛选、权限或图库变化后可处理项目少于目标时，实际可处理数量成为本次有效目标
- 剩余数量始终不小于 0；撤销会减少会话完成数并重新计算进度
- 视频不因达到目标而自动退出，用户仍可以继续向下浏览和整理

## 续接与队列不足

会话目标保存在设置中，新会话读取最新值；Deck 的加载窗口与目标无关，因此修改目标不会把连续队列缩小到目标数量。照片队列在目标未达到但已经确认没有可处理项目时，以现有动作生成本次总结；视频在队列耗尽时显示现有空态。
