# 统计事件账本口径

## 目的

日报、趋势、成就和年度报告都以 `cleanup_events` 为唯一的用户操作事实来源。`user_stats` 只作为首页快速展示的物化缓存，不定义新的统计口径。

## 一行事件的含义

- 每个成功提交、确实改变或记录了一个媒体操作的媒体项写一行事件
- `operationId` 对应本地 `operation_history.id`；撤销/恢复事件通过 `reversalOfEventId` 指向被抵消的原事件
- `photoDelta`、`videoDelta`、`sizeDeltaBytes` 和 `favoriteDelta` 是可以用于聚合的有符号净影响；原始用户事件通常为正，恢复或补偿事件可以为负
- `mediaSizeBytes` 保存受影响媒体体积，`sizeDeltaBytes` 保存对“标记可释放空间”统计的有符号净影响；两者不能混用
- `affectedMediaCount` 表示本行受影响的媒体数，`actionCount` 表示用户提交的操作数；二者不能互相替代
- `occurredAt` 保存毫秒时间戳，`localDate` 使用设备当前时区生成，按 `[start, end)` 时间窗口查询
- 不保存 URI、文件名、指纹、缩略图或其他可反推出媒体内容的敏感信息

## 事件类型

| 类型 | 统计影响 |
| --- | --- |
| `kept` | 记录保留操作；仅首次把媒体从未处理状态转为已处理时增加对应媒体净计数 |
| `favorited` | 记录收藏操作；收藏增量单独进入 `favoriteDelta` |
| `moved_to_app_trash` | 记录进入看了么应用回收站；体积表示“标记可释放”的空间，不宣称已经从设备释放 |
| `restored` | 记录从应用/系统回收站恢复；抵消对应待删事件的净计数和标记空间 |
| `compensated` | 记录保留或收藏等非回收站操作的撤销补偿，不删除原事件 |
| `permanently_deleted` | 记录系统授权后的永久删除动作；不重复计算已经由应用回收站标记的体积 |
| `archived_moved` | 记录归档移动到文件夹；动作数和受影响媒体数增加，但不虚构释放空间 |

幂等失败或重复点击没有状态变化时不新增事件。跨媒体批量操作若由多个媒体操作组成，分别保留媒体项事件；查询同时提供动作数和受影响媒体数，避免文案混淆。

撤销只追加 `restored` 或 `compensated` 事件并标记原操作已撤销，绝不删除历史事件。这样同一序列在日报、成就和年度窗口内可以对账。
