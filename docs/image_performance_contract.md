# 图片加载与预取合同

## D07a

- 应用继续使用单一共享 Coil `ImageLoader`，避免每个页面创建独立缓存
- 普通设备保留当前 30% 内存缓存比例和既有预取窗口，等待真实设备基准后再调参
- Android 标记为 low-RAM 的设备使用 15% 内存缓存；网格首轮、滚动前后窗口和清理 Deck 高分辨率预取都会缩小
- `onTrimMemory` 将系统内存压力传给 Coil 内存缓存；`onLowMemory` 清空内存缓存。磁盘缓存仍由 Coil 上限和应用启动时的后台裁剪共同约束
- 共享 loader 的事件监听器只在进程内累计不含媒体路径的计数：请求数、内存/磁盘命中、解码次数、取消、错误、请求像素和解码像素。调试构建每 50 个完成事件输出一次摘要，Release 不输出日志
- 网格、今日回顾和回收站预取统一跳过已在内存缓存中的请求；预取改为由 `LaunchedEffect` 持有的可取消挂起调用，页面离开时不会继续向后台追加未消费的任务
- low-RAM 设备已应用更小的首轮/滚动窗口和清理 Deck 高分辨率请求上限；普通设备仍保持原窗口，避免无基准数据的过度收缩
- 现阶段没有连接设备，因此没有宣称首图时延、PSS、GC、丢帧或低内存杀进程验证；普通设备预取窗口不因猜测而改变

只有获得长图、RAW/GIF、1k/10k 网格和快速反向滚动数据后，才调整普通设备窗口。
